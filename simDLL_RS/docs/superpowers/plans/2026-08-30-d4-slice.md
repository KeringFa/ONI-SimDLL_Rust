**目标：** 把温度阶段的并行工作单元从「一个已发现世界」细化到「32×32 切片」，先做串行执行版并证明与原版逐位一致，再接 rayon 并行。

### 2. 逐位一致的依据

格 X=(r,c) 在串行下被写入的**固定序列**：

| 序 | 来源 | X 的角色 |
|---|---|---|
| 1 | 格 (r-1,c) 的下邻配对 | b |
| 2 | 格 (r,c-1) 的右邻配对 | b |
| 3 | 格 (r,c) 的背墙 | — |
| 4 | 格 (r,c) 的右邻配对 | a |
| 5 | 格 (r,c) 的下邻配对 | a |
| 6 | 格 (r,c) 的状态转换 | — |

`compute_pair_delta` 与 `pair_allowed` 都**只读 `sim.cells` 不可变快照** → delta 值与执行顺序无关。唯一与顺序有关的是累加（`u.temperature[cell] += delta` 是读改写）。只要按上表顺序应用，浮点结果逐位相同。

### 3. 门控条件按方向不同（必须逐个精确复刻）

设 X=(r,c)，`w`/`h` 为**全局**网格宽高：

| delta | 源格 | 边界门控 |
|---|---|---|
| `d_up` | (r-1, c) 的下邻 | `r >= 1 && r < h - 1 && c < w - 1` |
| `d_left` | (r, c-1) 的右邻 | `c >= 1 && c < w - 1 && r < h - 1` |
| `d_right` | (r,c) 自己的右邻 | `c + 1 < w - 1 && r < h - 1 && c < w - 1` |
| `d_down` | (r,c) 自己的下邻 | `r + 1 < h - 1 && r < h - 1 && c < w - 1` |

（`r >= 1` / `c >= 1` 是为了避免 `cell - w` / `cell - 1` 下溢；其余项复刻源格的循环守卫 + 方向门控。所有项都隐含 `cell` 自身在 [0, w*h) 内。）

### 4. ⚠️ 区域 halo：串行会写到区域之外

门控用的是**全局** `w`/`h`，不是区域边界。所以格 (r, max_x-1) 的右邻配对会写到 `max_x` —— **已在区域之外**（落在星球间隙）。串行确实写了这一列和一行。

处理规则（**必须实现**）：

| 邻居位置 | 做法 |
|---|---|
| 邻居在本切片内 | 只应用自己那一半 |
| 邻居在**另一个切片**内 | 只应用自己那一半（邻居那半由对方算） |
| 邻居**不属于任何切片**（区域外 halo） | **两半都应用** |

安全前提：任意两个区域之间至少间隔 2 格（`BestFit.cs` 的 `Rect` +2 膨胀保证），所以区域外 halo 格绝不会落入另一个区域的处理集，不会有第二个写者。

```rust
// temperature.rs，紧跟 update_temperature_pair 之后

/// 计算一对格子间的温度交换增量。**只读 `sim.cells` 不可变快照**，无副作用。
///
/// `boundary_ok` 由调用方传入 —— 边界门控按方向而异，不能统一套用；
/// `|ΔT| >= 1` 与 `pair_allowed` 两道数值门控在本函数内部判定。
///
/// 返回 `(delta_a, delta_b)`；门控不通过返回 `None`。
pub(crate) fn compute_pair_delta(
    sim: &SimData,
    a: usize,
    b: usize,
    boundary_ok: bool,
) -> Option<(f32, f32)> {
    if !boundary_ok {
        return None;
    }
    if sim.cells.ptr.is_null() || sim.updated_cells.ptr.is_null() {
        return None;
    }
    if !pair_allowed(sim, a, b) {
        return None;
    }

    let (t_a, t_b, hc_a, hc_b, k_total) = {
        let c = unsafe { &*sim.cells.ptr };
        if a >= c.temperature.len() || b >= c.temperature.len() {
            return None;
        }
        let (t_a, t_b) = (c.temperature.get(a), c.temperature.get(b));
        if (t_a - t_b).abs() < 1.0 {
            return None;
        }
        let (elem_a, elem_b) = (c.element_idx.get(a), c.element_idx.get(b));
        let (Some(etd_a), Some(etd_b)) = (
            get_element_temperature_data(elem_a),
            get_element_temperature_data(elem_b),
        ) else {
            return None;
        };
        let (hc_a, hc_b) = (
            c.mass.get(a) * etd_a.specific_heat_capacity,
            c.mass.get(b) * etd_b.specific_heat_capacity,
        );
        if hc_a <= 0.0 || hc_b <= 0.0 {
            return None;
        }
        let k = combine_conductivity(
            c.insulation.get(a),
            etd_a.thermal_conductivity,
            c.insulation.get(b),
            etd_b.thermal_conductivity,
        );
        let mult_a = surface_multiplier_pair(&etd_a, etd_b.state);
        let mult_b = surface_multiplier_pair(&etd_b, etd_a.state);
        (t_a, t_b, hc_a, hc_b, k * mult_a * mult_b)
    };

    // 原版约定：冷侧在前（T_a ≤ T_b）调用 precise；否则 swapped 后映射回
    let (new_a, new_b) = if t_a <= t_b {
        calculate_temperature_exchange_precise(0.25, k_total, 0.2, t_a, hc_a, t_b, hc_b)
    } else {
        let (nb, na) =
            calculate_temperature_exchange_precise(0.25, k_total, 0.2, t_b, hc_b, t_a, hc_a);
        (na, nb)
    };

    let c = unsafe { &*sim.cells.ptr };
    Some((new_a - c.temperature.get(a), new_b - c.temperature.get(b)))
}

/// 把 `delta` 累加进**一个**格子。调用方保证该格子归自己所有。
///
/// 钳制 `[1.0, 10000.0]` 与串行版 `update_temperature_pair` 的逐次钳制一致
/// （串行也是每次应用后钳制，不是累加完再钳）。
pub(crate) fn apply_delta(sim: &mut SimData, cell: usize, delta: f32) {
    if sim.cells.ptr.is_null() || sim.updated_cells.ptr.is_null() {
        return;
    }
    unsafe {
        let u = &mut *sim.updated_cells.ptr;
        if cell >= u.temperature.len() {
            return;
        }
        let v = delta + u.temperature.get(cell);
        u.temperature.set(cell, v.max(1.0).min(10000.0));
    }
}
```

> **不要用 `std::ptr::eq(g1, g3)` 判断重建。** `SliceCache.grid` 是
> `Option<SliceGrid>` **内联**存储，重建只是替换里面的值，`&SliceGrid` 的地址
> 在 `SliceCache` 内的固定偏移上，**重建前后是同一个地址** —— 那条断言恒为真，
> 测不出任何东西。而且连着两次 `cache.get()` 里 `g1` 还持着不可变借用，
> 第二次要 `&mut`，是借用检查错误。
>
> 「签名未变则不重建」这个契约本身不可观测，所以缓存必须暴露一个
> `generation` 计数器作为可断言信号 —— 没有信号的契约是假契约。

```rust
#[test]
fn cache_rebuilds_only_when_signature_changes() {
    let b = RegionBounds { min_x: 1, min_y: 1, max_x: 71, max_y: 41 };
    let mut cache = SliceCache::default();
    cache.get(&[b], 32, 80, 50);
    let gen1 = cache.generation();
    assert_eq!(gen1, 1, "首次构建应记 1 代");
    // 同签名再取：不重建
    cache.get(&[b], 32, 80, 50);
    assert_eq!(cache.generation(), gen1, "签名未变不应重建");
    // 换区域：重建
    let b2 = RegionBounds { min_x: 1, min_y: 1, max_x: 91, max_y: 41 };
    cache.get(&[b2], 32, 80, 50);
    assert_eq!(cache.generation(), gen1 + 1, "区域变化应重建一次");
    // 换切片尺寸：也要重建（尺寸参与签名）
    cache.get(&[b2], 16, 80, 50);
    assert_eq!(cache.generation(), gen1 + 2, "切片尺寸变化应重建");
    // invalidate 后强制重建
    cache.invalidate();
    cache.get(&[b2], 16, 80, 50);
    assert_eq!(cache.generation(), gen1 + 3, "invalidate 后应重建");
}
```

```rust
/// 一个切片。边界为排他上界，与 `RegionBounds` 语义一致。
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct SliceBounds {
    /// 全局序号（区域序 → 行优先），用于事件定序合并。
    pub index: usize,
    /// 所属区域在 `active_regions` 中的下标，用于事件定序合并。
    pub region_index: usize,
    pub min_x: usize,
    pub min_y: usize,
    pub max_x: usize,
    pub max_y: usize,
}

impl SliceBounds {
    pub fn is_empty(&self) -> bool {
        self.min_x >= self.max_x || self.min_y >= self.max_y
    }
}

/// 一次构建出的完整切片列表。
pub struct SliceGrid {
    pub slices: Vec<SliceBounds>,
}

impl SliceGrid {
    /// 把每个区域切成 `size x size` 的切片；边界切片自动收窄。
    /// 切片不跨区域 —— 区域之间本就不相邻。
    pub fn build(regions: &[RegionBounds], size: usize) -> Self {
        let size = size.max(1);
        let mut slices = Vec::new();
        let mut index = 0usize;
        for (region_index, r) in regions.iter().enumerate() {
            if r.is_empty() {
                continue;
            }
            let mut y = r.min_y;
            while y < r.max_y {
                let y_end = (y + size).min(r.max_y);
                let mut x = r.min_x;
                while x < r.max_x {
                    let x_end = (x + size).min(r.max_x);
                    slices.push(SliceBounds {
                        index,
                        region_index,
                        min_x: x,
                        min_y: y,
                        max_x: x_end,
                        max_y: y_end,
                    });
                    index += 1;
                    x = x_end;
                }
                y = y_end;
            }
        }
        Self { slices }
    }
}

/// 切片缓存：仅在签名（区域列表 + 切片尺寸 + 网格尺寸）变化时重建，
/// 避免每帧分配。
#[derive(Default)]
pub struct SliceCache {
    signature: Option<(Vec<RegionBounds>, usize, usize, usize)>,
    grid: Option<SliceGrid>,
    /// 重建次数。缓存契约「签名未变则不重建」本身不可观测 ——
    /// `grid` 内联存储使 `&SliceGrid` 地址在重建前后相同，无法用作信号，
    /// 故显式记账，供测试断言与运行时诊断使用。
    generation: u64,
}

impl SliceCache {
    pub fn get(
        &mut self,
        regions: &[RegionBounds],
        size: usize,
        width: usize,
        height: usize,
    ) -> &SliceGrid {
        let sig = (regions.to_vec(), size, width, height);
        let changed = self
            .signature
            .as_ref()
            .map(|s| *s != sig)
            .unwrap_or(true);
        if changed {
            self.grid = Some(SliceGrid::build(regions, size));
            self.signature = Some(sig);
            self.generation = self.generation.wrapping_add(1);
        }
        self.grid.as_ref().expect("grid 已初始化")
    }

    /// 重建次数。首次 `get` 后为 1；签名未变则不再增长。
    pub fn generation(&self) -> u64 {
        self.generation
    }

    pub fn invalidate(&mut self) {
        self.signature = None;
        self.grid = None;
    }
}
```

```rust
// src/d4_slice/temperature.rs
//! 切片化的温度阶段。

use crate::a_framework::sim_data::SimData;
use crate::c2_physics::temperature::{
    apply_delta, compute_pair_delta, do_state_transition, get_element_temperature_data,
    update_temperature_for_backwall,
};
use crate::d1_activity::RegionBounds;
use crate::d4_slice::slice_grid::SliceGrid;
use crate::d4_slice::DEFAULT_SLICE_SIZE;

/// 格 `cell` 是否落在任一区域边界内（即是否会被某个切片覆盖）。
///
/// 由任务 3 的覆盖性测试可知，切片恰好无重叠、无缝地平铺每个区域，
/// 因此「被某切片覆盖」⟺「落在某区域边界内」，无需查切片表。
///
/// 用途：判断配对的邻居那半该由谁写。
/// - 邻居被覆盖 → 对方（或本切片自己的另一轮）会写，本轮跳过
/// - 邻居未被覆盖（区域外 halo，串行版实际会写到它）→ 本切片代写
///
/// 若后续 profile 显示这个 O(区域数) 判定是热点，再换成缓存位图；先按 YAGNI 走简单版。
fn is_owned(cell: usize, w: usize, regions: &[RegionBounds]) -> bool {
    let x = cell % w;
    let y = cell / w;
    regions
        .iter()
        .any(|r| x >= r.min_x && x < r.max_x && y >= r.min_y && y < r.max_y)
}

/// 单个格子的完整处理序列（顺序严格复刻串行）。
///
/// `own` 为 true 时表示本格归当前切片所有；`neighbor_owned` 返回某邻居是否
/// 归某个切片所有（不归属 → 本切片需连邻居那半一起应用，见任务说明第 4 节）。
fn process_cell(
    sim: &mut SimData,
    cell: usize,
    w: usize,
    h: usize,
    neighbor_owned: impl Fn(usize) -> bool,
) {
    let r = cell / w;
    let c = cell % w;

    // ---- 计算（顺序无关，只读快照；保留完整配对结果，halo 代写需要另一侧）----
    let pair_up = if r >= 1 && r < h - 1 && c < w - 1 {
        compute_pair_delta(sim, cell - w, cell, true)
    } else {
        None
    };
    let pair_left = if c >= 1 && c < w - 1 && r < h - 1 {
        compute_pair_delta(sim, cell - 1, cell, true)
    } else {
        None
    };
    let pair_right = if c + 1 < w - 1 && r < h - 1 {
        compute_pair_delta(sim, cell, cell + 1, true)
    } else {
        None
    };
    let pair_down = if r + 1 < h - 1 && r < h - 1 && c < w - 1 {
        compute_pair_delta(sim, cell, cell + w, true)
    } else {
        None
    };

    // ---- 应用（顺序严格：上 → 左 → 背墙 → 右 → 下 → 状态转换）----
    //
    // ⚠️ **上/左 与 右/下 的写入规则不对称**，根源是本格在配对中所处的位置不同。
    //
    // 串行版（`run_temperature_band`）每格只处理「右」「下」两对，本格是配对的
    // **第一**元素。因此任意一对 (A,B) 只在 **A 被处理时**才计算，且一次写满两半。
    // 对本格 X 的四个配对：
    //   - (X-w, X) 与 (X-1, X)：X 是**第二**元素。这一对只有在「那个邻居在区域内、
    //     它自己那轮会算」时才存在。邻居在区域外 → 串行版根本不算这一对，
    //     **X 那半也不能写**，否则就是多出来的贡献（区域顶行/左列必挂）。
    //   - (X, X+1) 与 (X, X+w)：X 是**第一**元素，只要 X 在区域内就无条件算。
    //     X 那半永远写；邻居那半串行版也会写（哪怕邻居在区域外 —— 那就是
    //     右/下边缘的 halo），所以邻居在区域外时必须由本格代写。
    //
    // 这条不对称规则同时保证并行安全：区域内格的写入只落在自己身上，
    // 跨格写入仅发生在无人拥有的 halo 上 —— 不存在两个切片写同一格。
    if let Some((_d_nb, d_self)) = pair_up {
        if neighbor_owned(cell - w) {
            apply_delta(sim, cell, d_self);
        }
        // 邻居那半永不代写：在区域内时它自己会写，不在时串行版不算这一对。
    }
    if let Some((_d_nb, d_self)) = pair_left {
        if neighbor_owned(cell - 1) {
            apply_delta(sim, cell, d_self);
        }
    }

    // 背墙：复刻串行门控
    {
        let do_bw = unsafe {
            let cc = &*sim.cells.ptr;
            let bw = &*sim.backwall.ptr;
            cell < cc.mass.len() && cell < bw.mass.len()
                && cc.mass.get(cell) > 0.0 && bw.mass.get(cell) > 0.0
        };
        if do_bw {
            update_temperature_for_backwall(sim, cell);
        }
    }

    if let Some((d_self, d_nb)) = pair_right {
        apply_delta(sim, cell, d_self);
        if !neighbor_owned(cell + 1) {
            apply_delta(sim, cell + 1, d_nb); // 右边缘 halo，无人会写 → 代写
        }
    }
    if let Some((d_self, d_nb)) = pair_down {
        apply_delta(sim, cell, d_self);
        if !neighbor_owned(cell + w) {
            apply_delta(sim, cell + w, d_nb); // 下边缘 halo，无人会写 → 代写
        }
    }

    // 状态转换
    let elem = unsafe { (*sim.cells.ptr).element_idx.get(cell) };
    if let Some(etd) =
        crate::c2_physics::temperature::get_element_temperature_data(elem)
    {
        crate::c2_physics::temperature::do_state_transition(sim, cell, &etd);
    }
}

/// 切片化的温度阶段（**串行执行版**，用于验证逻辑复刻正确性）。
pub fn run_temperature_sliced_serial(
    sim: &mut SimData,
    regions: &[RegionBounds],
    slice_size: usize,
) {
    if sim.cells.ptr.is_null() || sim.updated_cells.ptr.is_null() {
        return;
    }
    let w = sim.width as usize;
    let h = sim.height as usize;
    if w < 3 || h < 3 {
        return;
    }
    let grid = SliceGrid::build(regions, slice_size);
    let owned = |cell: usize| is_owned(cell, w, regions);
    for s in &grid.slices {
        // 注意：owned 判定的是「邻居是否被**任何**切片覆盖」，见下方 is_owned 说明
        if s.is_empty() {
            continue;
        }
        for y in s.min_y..s.max_y {
            for x in s.min_x..s.max_x {
                if y >= h - 1 || x >= w - 1 {
                    continue; // 复刻串行循环守卫
                }
                process_cell(sim, y * w + x, w, h, &owned);
            }
        }
    }
}
```

**关于 `process_cell` 的归属判定**（任务 4 已实现，此处仅说明，不要改）：

| 邻居归属 | 是否代写邻居那半 |
|---|---|
| 归本切片 | **否**（邻居会在自己那轮里写自己的） |
| 归另一个切片 | **否**（对方会写） |
| 不属于任何切片（区域 halo） | **是**（没别人会写） |

前两态行为相同，故判定就是一句话：**邻居是否被任何切片覆盖**（`is_owned`）。

**关于线程池**：`d4-slice` 复用 `d3_rayon::pool()` 这**同一个持久池**，
这是刻意的 —— 避免两条路线各建一个池造成嵌套池争抢（项目既有设计目标）。
因此 Cargo feature 写 `d4-slice = ["d3-rayon"]`（见任务 1），
**不需要**新建线程池，也**不要**动 `d3_rayon/mod.rs::pool()`。

并行入口：

```rust
use crate::globals::SendSyncPtr;

pub fn run_temperature_sliced_parallel(
    sim: &mut SimData,
    regions: &[RegionBounds],
    slice_size: usize,
) {
    // …同串行版的前置检查…
    let grid = SliceGrid::build(regions, slice_size);
    let sim_ptr = SendSyncPtr(sim as *mut SimData);
    let w = sim.width as usize;
    let h = sim.height as usize;
    // 归属判定：与串行版同一套规则（见任务 4 说明）
    let owned = |cell: usize| is_owned(cell, w, regions);

    crate::d3_rayon::pool().install(|| {
        use rayon::prelude::*;
        grid.slices.par_iter().for_each(|s| {
            if s.is_empty() {
                return;
            }
            // 每个切片**内部**仍是串行扫描 —— 这保证了每格的 delta 应用次序不变
            let local = unsafe { &mut *sim_ptr.get() };
            for y in s.min_y..s.max_y {
                for x in s.min_x..s.max_x {
                    if y >= h - 1 || x >= w - 1 {
                        continue;
                    }
                    process_cell(local, y * w + x, w, h, &owned);
                }
            }
        });
    });
}
```

> `crate::d3_rayon::pool()` 是现有的 rayon 持久池（`src/d3_rayon/mod.rs:40`）。
> 它只在 `d3-rayon` feature 下存在 —— 因此 `d4-slice` feature 必须同时开启
> `d3-rayon`，或把 `pool()` 移到公共位置。**实现时二选一：**
> 推荐后者 —— 把 `pool()` 从 `d3_rayon` 提到 `src/d4_slice/pool.rs`（或 `d2_thread`），
> 让两条路线共用同一个持久池，避免嵌套池争抢。

## 任务 7：调度层接入（方案 B：跨全部区域统一派发）+ 运行时开关

**为什么是方案 B 而不是「在区域任务内切片」**（实测数据支撑，见本文件末尾 §附录）：

D2 的 LPT 装箱把 9 个区域分到 7 组后，各组格数为
组A 43,840 / 组B 19,584 / 组C 19,584 / 组D 15,360 / 组E–G ≈ 13,800–14,300。
**组A 是平均的 2.2 倍**，它一个人就是关键路径。

若只在各组内部切片，组B 的线程跑完自己的温度后立刻转去做本组的 copy/气体/液体，
**无法回头偷组A 剩下的温度切片**（rayon 不会抢占一个正在跑串行阶段的线程）。
组A 那 43,840 格仍旧基本单线程 → 切片白切一半。

方案 B 把全部 147 片放进**一个** `par_iter`，在任何一组开始后续阶段之前跑完，
七线程均分 → 关键路径 43,840 → ≈20,064（2.2×）。

**已知边界**：本任务只修温度的失衡。屏障之后的气体/液体/后处理仍保持今天 2.2× 的
组间失衡，要等批次二把它们也切片。端到端收益取决于温度在阶段 A 的占比（当前无数据）。

- 修改：`src/c2_physics/mod.rs`（`update_data` 调度分支 + `run_region_physics_a` 拆分）

### ⚠️ 顺序陷阱（动手前必读）

`run_region_physics_a`（`src/c2_physics/mod.rs:21`）当前每区域的执行序是：

```
derive_natural_solid_strength(格子)   ← 第 32 行，在温度之前
温度                                   ← 第 35 / 60 / 69 行（三处调用点）
copy_updated_cells_to_cells[_region]   ← 第 73/75 行
气体压力 / 气体置换 / copy / 液体 / 太空真空 / PostProcess
```

把温度提升到全局切片后，**绝不能让 `derive_natural_solid_strength` 落到温度之后** ——
温度里的 `do_state_transition` 会改元素索引，derive 在它之后跑会得到不同结果。

正确顺序：

```
[逐区域] derive_natural_solid_strength
[全局]   温度切片并行（147 片，一个 par_iter）
[全局]   copy_updated_cells_to_cells
[逐区域] 气体压力 / 气体置换 / copy / 液体 / 太空真空 / PostProcess
```

因此 `run_region_physics_a` 需要拆成两半（**建议的拆法，实现者可按需调整命名**）：

```rust
/// 阶段 A 的前半：只做自然固体强度推导。温度已由 D4 全局跑完时由调用方跳过后续。
pub(crate) fn run_region_physics_a_pre(sim_data: &mut SimData, bounds: RegionBounds);

/// 阶段 A 的后半：copy + 气体 + 液体 + 太空真空 + PostProcess（不含温度）。
pub(crate) fn run_region_physics_a_post(
    sim_data: &mut SimData,
    bounds: RegionBounds,
    pp_bounds: RegionBounds,
    cosmic_intensity: f32,
    parallel: bool,
);

/// 保持原语义的完整入口 = pre + 温度 + post。D1/D2/串行路径继续用它。
pub(crate) fn run_region_physics_a(
    sim_data: &mut SimData,
    bounds: RegionBounds,
    cosmic_intensity: f32,
    parallel: bool,
);
```

`skip_temperature` 的透传路径：`update_data` → `run_parallel_pipeline` /
`run_d1_pipeline` / `run_serial_regions` → `run_region_physics_a`。
实现时优先用**显式参数**透传，不要用 thread-local / 全局标志（可测性太差）。
