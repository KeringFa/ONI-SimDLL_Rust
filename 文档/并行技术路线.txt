# simDLL_RS 并行技术路线（D1 / D2）

## 1. 概述

项目在 Rust 重写 SimDLL 的基础上，为多活动区域（多星/多已发现世界）提供两条
并行路线，由运行时调度器按模式选择：

- D1：1 星 1 线程 + 亲和分组（自研持久线程执行器）
- D2：rayon 工作窃取（LPT 面积装箱）

两条路线共享同一套约束：单区域/单星永远走串行（与原版行为零变化）、阶段 B
（组件）始终串行、太空员舱集群单独合并、预留物理线程数同时约束两者。

## 2. 调度器（scheduler.rs）

模式由接口 mod 经 `RS_SetSchedulerMode` 设置（OnLoad 时，SIM_Initialize 之前）：

| 模式 | 值 | 行为 |
|------|----|------|
| Auto | 0 | 多区域 → D2；单区域 → 串行 |
| D2 | 1 | 强制 rayon 装箱 |
| D1 | 2 | 强制方向 1；无超线程拓扑时回退 D2 |

预留物理线程数由 `RS_SetReservedCores` 设置（1～4，默认 1），经
`scheduler::reserved_cores()` 统一读取，同时约束 D1 分组与 D2 池线程数。
接口 mod 侧为「预留物理线程数量」输入项（ReserveCores）。

## 3. CPU 拓扑检测（affinity.rs）

- 使用 Windows `GetLogicalProcessorInformationEx`（RelationProcessorCore），
  逐条按 `Size` 推进，用 `GROUP_AFFINITY.Mask` 的位计数得出每个物理核的
  逻辑处理器数（物理核数、逻辑核总数、per-core 列表）。
- 回退策略：
  1. API 调用失败或长度为 0 → 用 `available_parallelism`（视为无超线程）；
  2. 解析成功但物理核 ≤1 且系统逻辑核 ≥4（异常环境）→ 按逻辑核/2 近似物理核，
     每核 2 逻辑处理器，避免调度路径把 CPU 当成 1 核。
- 拓扑缓存：进程内只查询一次（OnceLock）。

## 4. D2 路线：rayon 工作窃取（mod.rs + pipeline.rs + bin_pack.rs）

### 线程池

- `G_RAYON_POOL` 为 OnceLock 持久池，只在首次使用时构建，之后复用；
- 线程数 = 物理核数 − 预留数（下限 1）。

### 装箱与执行

- `bin_pack_region_groups`：LPT 贪心装箱——区域按面积降序，逐个放入当前累计
  面积最轻的组；组数 = min(区域数, 线程数)；不拆世界。
- `run_parallel_pipeline`：每区域独立事件缓冲（region sink），rayon scope
  按组提交任务（组内逐区域串行），scope 结束后按区域序合并事件。
- 阶段 A（网格物理，含温度内联、区域局部 CopyFrom）与阶段 C（收尾）并行；
  阶段 B（组件）串行。

## 5. D1 路线：1 星 1 线程 + 亲和分组（d1_pipeline.rs + affinity.rs）

### 分组算法（assign_groups）

输入：普通世界 tiles（不含太空员舱集群）、拓扑、预留数。

- 物理核组：前 `physical_cores − reserve` 个大世界各独占一个物理核；
- 超线程组：剩余最小世界按 tiles 升序两两合并（组上限 19584，覆盖变体后上限），
  复用物理核组的空闲逻辑核；
- 太空员舱集群（`is_module_cluster`：32×32 = 1024 tiles，对应
  HabitatModuleMedium/Small）单独一个超线程组，不参与普通世界分组。

### 执行器

- 持久线程执行器：每组一个常驻 `std::thread`，mpsc 信号 + Barrier 帧同步；
- 线程只在分组变化时重建，避免每帧 spawn 开销；
- 亲和性绑定已移除（OS 自由调度；实测与 rayon 持平，4C8T 下线程数 = 组数
  更充分，作为玩家可选优化保留）；
- 无超线程或拓扑异常 → 回退 D2。

## 6. 两条路线的共同约束

1. 多区域才并行：活动区域来自「已发现世界」（SimActiveRegion）；单区域/单星
   永远串行，与原版一致。
2. 预留物理线程数同时生效：D1 改变物理核组数（`physical − reserve`），D2 改变
   rayon 池线程数。
3. 阶段 B 始终串行：组件（发射器/换热/疾病等）注册顺序敏感，不并行。
4. 事件合并：并行任务写各自缓冲，按区域序合并，不跨线程直接写全局事件。
5. feature 门控：本目录受 `d3-rayon` feature 控制；不带 feature 编译即
   v1 稳定版（不包含并行路线）。

## 7. 关键文件

| 文件 | 职责 |
|------|------|
| src/d3_rayon/scheduler.rs | 调度模式、`RS_SetReservedCores`、`reserved_cores()` |
| src/d3_rayon/mod.rs | `reserve_cores()`、rayon 持久池、并行门控 |
| src/d3_rayon/affinity.rs | CPU 拓扑检测、D1 分组、拓扑 fallback 加固 |
| src/d3_rayon/bin_pack.rs | D2 LPT 面积装箱 |
| src/d3_rayon/pipeline.rs | D2 并行入口（阶段 A/C + 事件合并） |
| src/d3_rayon/d1_pipeline.rs | D1 持久执行器、太空员舱集群识别 |
| src/c2_physics/mod.rs | 调度分发（串行 / D1 / D2 三分支） |
| src/d3_rayon/perf_probe.rs | simdll_perf.log（mode/regions/threads/avg/max） |

## 8. 调度时序备忘

- 接口 mod OnLoad：RS_LoaderInstall → ModConfig.Load/Apply（含
  `RS_SetLogEnabled` + `RS_SetReservedCores`）→ `RS_SetSchedulerMode`；
- rayon 池（D2）与 D1 执行器都在首个 sim 帧才构建，配置均在构建前生效；
- 修改配置后需重启游戏生效（OnceLock 池 / 执行器不热重建）。
