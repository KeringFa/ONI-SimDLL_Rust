# 冒泡机制（Bubble）调查记录

日期：2026-08-10
范围：Thermal Gas Fissure（UnderwaterVent）/ Flue Coral（OxyCoral）/ Blowter（PufferFish
  VentBubbleStates）/ BubbleSpawner（PacuCleaner 等）的气泡发射与 SimDLL 的关系
基准：Assembly-CSharp 反编译 + simDLL_RS Rust 源码

## 一、结论（先看这个）

1. **气泡的发射、上浮、破裂判定全部在 C# 端（BubbleManager），SimDLL 完全不参与
   气泡粒子的运动**。气泡不是 sim 元素，只是带质量/温度/病菌的视觉粒子。
2. **SimDLL 只参与"气泡破裂入格"那一刻**：破裂时 C# 调用
   `SimMessages.AddRemoveSubstance(cell, element, ...)` → `ModifyCell(ReplaceType.None)`
   （Add 模式）→ Rust `process_cell_modifications` 的 replace_mode 0 分支 →
   `add_gas / add_liquid / add_solid` 按元素形态分派 → 质量/温度合并 + change_substance 事件。
3. 因此 **Rust 侧不需要为冒泡新增任何机制**，只要 ModifyCell(Add) 语义正确即可
   （当前已实现，2026-08-02 修复过 Add 覆盖质量问题）。项目实测正常符合预期。
4. 关键原版行为：**气泡在液体中上浮期间不与周围液体换热、不占格子**，温度保持
   发射时的值，直到破裂入格后才开始正常换热/参与气体模拟。

## 二、发射端（C# 状态机，均不经过 sim）

### 1. Thermal Gas Fissure（间歇泉，ID=UnderwaterVent）
- 文件：UnderwaterVentConfig.cs / UnderwaterVent.cs
- 数据（Config.Data）：bubbleElement=Methane、bubbleTemp=373.15K、
  bubbleMassRate=1/12 kg/s、solidElement=Sulfur、solidMass=1000kg、
  buildUpDuration=1200s、bubbleSpawnOffset=(1, 2.5)
- 状态机：off（未浸没/被掩埋）↔ on.erupting（每秒 EruptionUpdate）→ BuildUp≥1 →
  on.blocked（硫磺堵死）→ Marine Drill（UnderwaterVentDrill）清除 → unblock →
  SpawnSolidDebri 生成硫磺**碎片实体**（不走 sim 消息，纯 C# 生成物体）
- 冒泡：每 SIM_1000ms 发 1 个甲烷气泡（1/12 kg），固定单格 → "单格冒泡" ✓

### 2. Flue Coral（植物，ID=OxyCoral）
- 文件：OxyCoralConfig.cs / OxyCoral.cs
- 数据：OxygenProductionRate = 1.5× 复制人耗氧率（≈180 g/s）、MinLuxRequired=2500、
  OutputBubbleCells = [(-1,1), (0,1), (1,1)]（3 格）
- 状态机：grow → noProducing（noLight/wilted/dead）↔ producing（需光照≥2500 lux）
- 冒泡：producing 状态每 SIM_1000ms ProduceOxygenUpdate——从 3 格中
  `Random.Range(0, len)` **随机取 1 格**，质量 = 产率×dt（野生 ×0.25），≥1e-9 才发
  → "随机三格中一个冒泡" ✓

### 3. Blowter（动物，PufferFish 的 VentBubbleStates）
- 文件：BasePufferFish.cs / VentBubbleStates.cs
- 数据：element=Oxygen、emitMass=1kg（Def 默认）
- 流程：吃海莴苣（SeaLettuce）→ 胃里积氧（Storage，容量 OXYGEN_STORAGE_CAPACITY）
  → full（膨胀 30 秒）→ venting（每秒 EmitBubble，从 Storage 扣 min(mass, 1kg) 发气泡）
  → venting_pst → empty；复制人可主动抽氧（dupe_venting，0.25kg/s、y 偏移 0.75）
- 冒泡：venting 状态只播放 deflate 动画、不移动 → "单格冒泡、冒泡时不动" ✓

### 4. BubbleSpawner（通用组件，PacuCleaner 等建筑/生物）
- 文件：BubbleSpawner.cs（PacuCleanerConfig.cs 添加）
- 订阅 Storage 变化事件（-1697596308）：库存中该元素质量 ≥ emitMass 时，
  扣 emitMass（±emitVariance 随机）并 SpawnBubble（温度用库存 PrimaryElement 温度）

## 三、气泡本体（C# BubbleManager，纯 C#）

- 文件：BubbleManager.cs（单例，ISim33ms + IRenderEveryTick）
- 数据：按 (worldIdx, archetype) 分桶存储 position / elapsedTime / mass /
  temperature / sizeLevel / alpha / disease；**可序列化（随存档保存）**；
  mass<1e-9 不生成；sizeLevel 由 MassTresholds {0.1, 0.3} 分档
- 上浮：Sim33ms 每 33ms 按 archetype 速度（默认 (0,1)）移动气泡
- 破裂判定 ShouldPop（BubbleManager.cs:578-585）：
  - 气泡所在格元素 == 气泡元素 → 破裂（进入同元素气体聚集区）
  - 否则：不在液体中（到达液面/气体/真空区）→ 破裂
  - 破裂时修正：目标格是固体 → 用气泡原位置格；目标格是异种液体 →
    取上方格（若为气体/真空）
- 破裂动作（BubbleManager.cs:605）：
  `SimMessages.AddRemoveSubstance(cell, element, CellEventLogger.Instance.FallingWaterAddToSim,
   mass, temperature, disease.idx, disease.count)` —— **这是入 sim 的唯一入口**

## 四、SimDLL 侧（Rust）

- C# 端 SimMessages.AddRemoveSubstance（SimMessages.cs:1371-1384）→
  ModifyCell(ReplaceType.None) = Add 模式
- Rust：frame_processor.rs `process_cell_modifications`（:388）replace_mode 0 分支：
  - 按**被添加元素**形态分派（原版 SimDLL_Source.c L134880-135018）：
    气体 → liquid_flow::add_gas（:2734）、液体 → add_liquid（:2649）、
    固体 → add_solid（:2816）
  - 负质量 → 同形态减质量，≤0 清格 + change_substance
  - 温度按质量加权混合并钳制到 [min, max]（与 merge 语义一致）
  - 之后的气体上升/扩散/分层/液体推挤全部走既有气体模拟，无需气泡特判

## 五、需要留意的原版行为（回归测试要点）

1. 气泡上浮期间**不换热、不碰撞**——纯视觉，温度保持发射值；
   破裂入格后气体才与邻格换热。若看到"气泡气体温度与液体不同"属正常。
2. 破裂入格用 Add 模式：目标格已是同元素时**合并**（质量相加、温度混合），
   不是覆盖——Add 覆盖质量是历史 bug，2026-08-02 已修复（add_gas/add_liquid 语义）。
3. 硫磺堵塞（Fissure）的清除产物是**碎片实体**（C# SpawnRockDebri），不走
   ModifyCell 消息，与 SimDLL 无关。
4. BubbleManager 有粒子上限（RenderEveryTick 16249 个/世界），超出丢弃渲染，
   不影响 sim。
