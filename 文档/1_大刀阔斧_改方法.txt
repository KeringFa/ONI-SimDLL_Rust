================================================================================
Rust 版本特性适用性分析（大刀阔斧·改方法）
分析日期：2026-09-06
工具链：Rust 1.98.0 stable（已安装）
目标项目：simDLL_RS（缺氧 SimDLL Rust 重实现）
================================================================================

分析范围：Rust 1.89 — 1.98 稳定版中与性能/SIMD/内存/浮点相关的特性。
结论：按"实际收益 × 落地难度"排序，区分"能用"和"不适用"。

================================================================================
一、第一梯队：有实际收益且风险低
================================================================================

【1】core::hint::cold_path（1.95 稳定）— 零风险，建议直接用
  作用：标记热循环中几乎不会走的分支，让编译器放到冷路径，改善指令缓存
        和分支预测。
  适用位置：
    - run_temperature_band：元素查找失败（None 分支）、越界 continue
    - run_gas_pressure_task：gas_pair_ok 失败分支、corner_blocked 分支
    - update_pressure：元素表查找失败、transfer <= 0 提前返回
    - do_state_transition：相变阈值未命中的 return false
  用法示例：
    if let (Some(ea), Some(eb)) = (...) { /* 热路径 */ }
    else { core::hint::cold_path(); }
  预估收益：1-3% 帧时间。
  风险：零。纯编译器提示，不改变任何数值或行为。
  工作量：半小时，逐处添加。

【2】安全 #[target_feature] + x86 AVX2 内联函数（1.89 稳定）— 收益最大
  背景：Rust 1.89 稳定了 ~867 个 x86 SIMD 内联函数和 25 个 target_feature，
        此前写 AVX2 需要 unsafe 整块包裹，现在可以按函数安全标记。
  适用模块：温度计算（run_temperature_band）——每格独立做背墙换热 +
        右/下邻换热 + 状态转换，是天然的 SIMD 目标。
  用法示例：
    #[target_feature(enable = "avx2")]
    fn run_temperature_band_avx2(sim: &mut SimData, bounds: RegionBounds,
                                 row_start: usize, row_end: usize) {
        // 用 std::arch::x86_64::__m256 做 8 路并行温度计算
    }
    // 运行时检测：
    if is_x86_feature_detected!("avx2") {
        run_temperature_band_avx2(...)
    } else {
        run_temperature_band(...)  // 标量回退
    }
  预估收益：温度模块 20-40% 加速（温度占帧时间 30-40%），综合 5-15% 帧时间。
  风险：需要保证 AVX2 路径与标量路径数值一致（或差异在可接受范围内）。
        不支持 AVX2 的 CPU 走标量回退，行为不变。
  工作量：最大。需要重写温度内层循环，处理边界（非 8 对齐的行尾）。
  注意：std::simd（portable SIMD）仍在 nightly，1.98 不能用；
        必须用 std::arch::x86_64 平台特定内联函数。

【3】f32::mul_add（FMA，早已稳定）— 小收益，需评估数值影响
  作用：融合乘加，一次舍入代替两次，且 CPU 原生 FMA 指令更快。
  适用位置：
    - calculate_temperature_exchange_precise：equilibrium 计算
    - combine_conductivity：iv * tc
    - update_temperature_pair：mass * specific_heat_capacity
    - 辐射 25 格核：mass * 0.001 * rads_per_1000 * weight
  用法示例：
    let hc = mass.mul_add(shc, 0.0);  // 替代 mass * shc
  预估收益：温度/辐射模块 1-3%。
  风险：FMA 改变舍入次数 → 数值与原版有微小差异。和代数浮点同类问题，
        但影响范围更小（只在乘法链）。需跑 588 测试验证。
  工作量：小，逐处替换。

================================================================================
二、第二梯队：写法改进，性能差异小
================================================================================

【4】as_ref_unchecked / as_mut_unchecked（1.95 稳定）— 代码更清晰
  作用：替代 unsafe { &*sim.cells.ptr } 的写法，明确表达"不检查 null"。
  用法：
    let cells = sim.cells.ptr.as_ref_unchecked();  // 替代 &*ptr
  性能：与 &*ptr 基本一致（都是 unsafe，编译器都不插运行时检查）。
  价值：语义更清晰，可读性更好，适合全项目统一替换。
  工作量：中等，全局替换。

【5】代数浮点方法 algebraic_add/sub/mul/div/rem（1.98 稳定）— 已评估
  详见 1_优化点_豆包2.1_Turbo.txt 中的讨论。
  结论：辐射 25 格核加权和可以先试（有 clamp 保护），温度先不动。
  风险：改变运算顺序 → 数值偏离原版（原版 MSVC /fp:precise 不做重排）。

================================================================================
三、第三梯队：不相关或收益极小
================================================================================

| 特性 | 版本 | 不适用原因 |
|------|------|-----------|
| 整数位操作 isolate_highest_one 等 | 1.97 | 项目用 properties 位掩码但操作简单，收益极小 |
| 新 core::range::Range（Copy） | 1.96 | RegionBounds 已经是 Copy，没必要换 |
| cfg_select! | 1.95 | 编译期条件选择，项目无此需求 |
| assert_matches! | 1.96 | 测试用，不影响运行时 |
| format_into / NumBuffer | 1.98 | 整数格式化，项目无热点格式化 |
| AtomicPtr::update / try_update | 1.95 | 元素表快照已用 AtomicPtr load，update 只简化写法 |
| std::simd portable SIMD | — | 仍在 nightly（portable_simd #86656），1.98 不能用 |
| v0 symbol mangling 默认 | 1.97 | 编译期符号，不影响运行时性能 |
| str::substr_range / [T]::subslice_range | 1.98 | 字符串/切片操作，项目无热点 |
| if-let guards in matches | 1.95 | 语法糖，不影响性能 |
| MaybeUninit<[T;N]> 转换 | 1.95 | 缓冲区初始化，项目无此模式 |
| Vec::push_mut / insert_mut | 1.95 | 事件收集可用但非热点 |
| async 任务调度 10% 加速 | 1.96 | 项目不用 async |

================================================================================
四、建议落地顺序
================================================================================

1. 【先做】cold_path — 半小时，零风险，直接提交
2. 【再做】FMA 实验 — 温度模块加 mul_add，跑 588 测试，通过则游戏内对比
3. 【然后】辐射代数浮点实验 — 25 格核重构为求和后用 algebraic_add
4. 【最后】AVX2 温度 — 工作量最大但收益最高，等前面验证稳定后再动

================================================================================
五、关于是否需要查 1.95 以下版本
================================================================================

不需要。理由：
1. Rust 向后兼容——1.98 包含所有之前版本稳定的特性，查更早版本
   只是确认"有没有遗漏的老特性"，而不是"能不能用"。
2. 最近几年最大的性能相关特性已覆盖：
   - 1.89：安全 #[target_feature] + 867 个 SIMD 内联函数（最大）
   - 1.95：cold_path + as_ref_unchecked
   - 1.98：代数浮点
   - FMA、slice::fill、array::from_fn 等老特性项目已自然使用
3. 1.89 之前的版本稳定的特性主要是语言语法和库 API，不是性能相关的。
4. 如果有遗漏，也是小特性，收益不大。

唯一值得快速确认的是 1.90-1.94 之间是否有性能相关的稳定化，
但从发布说明规律看，这几个版本没有大的性能特性。
