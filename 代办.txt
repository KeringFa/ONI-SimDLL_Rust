## [待实测] 管道温度管理器按原版全量重写（2026-08-02，管道水珠/水泵）

- **现象**：原版存档的管道水珠在加载后被清空；水泵排不进水管（Pipe Blocked，储罐 20kg 满）。
- **根因**：C# 管道系统每帧从 sim 的 `ConduitTemperatureManager_*`（Add/Set/Update）读写管道温度；此前简易版句柄无版本位、释放立即复用 → 重建/拆除后句柄↔数组索引错位，C# 温度数组被 sim 覆盖后读到错误/0 温度。
- **关键新证据**：用户实测「莫名版本」（my_Project\simDLL_RS_Kit\simDLL_RS）——水珠能被加载，但**水泵同样吸不了水/排不进管**。结论：温度管理器是水珠加载的必要条件（非充分），水泵 Blocked 另有第二根因，需实测定位。
- **已实现**（严格对照原版 SimDLL_Source.c L94814-95886，未抄神秘版本）：
  - 版本句柄 `handle = (version<<24)|index`，8bit 版本复用计数；
  - 延迟释放双缓冲：Remove 入缓冲，sim 线程每轮 `ReleaseQueuedHandles`（已挂接 sim_thread L2113 位置）两轮后 swap-remove 回收；
  - Add/Set 按元素表构造 Data（SHC×mass、TC、low/high 过渡温度，>10000 重置默认温度）；
  - Update 全量换热：insulated→min 导热 / 否则 avg、热流×50、能量×dt×0.001、钳制防过冲、能量守恒取小值、交叉检测加权平均、NaN 回退、显著能量发 MODIFY_BUILDING_ENERGY(0xAF9B1296) 16B、±3.0 滞回相变 → frozen/melted；
  - Update 第二参数长度取 GDU.num_building_temperature_info（C# 传的即 GDU buildingTemperatures 指针，Game.cs L1086）。
- **探针**：Add 记录返回句柄/版本，Set/Remove/Update 计数，Update 记录 building_len——用于下次实测定位水泵根因。
- 单测 11 条（句柄版本/延迟释放/换热数值/隔热/相变/交叉/跳过逻辑）；全量 323 测试串行全过；release 编译成功。

### 太阳光根因修复（2026-08-04，用户实测：仅顶部行亮 / 真空阻隔光）

**根因（NaN 毒化阳光列）**：
- 真空 `defaultMass=0`（元素 YAML）→ `massScale = 1.0/0.0 = INFINITY`
  （03_elements.c L362-368 反编译：非固体 = 1/defaultMass）；
- 空间生态区真空格质量=0 → 曝光函数 `absorb = massScale × mass =
  INFINITY × 0 = NaN`；`absorb >= 1.0` 对 NaN 为 false → NaN 进入
  `sun -= absorb×factor` 与 sun 缓冲 → 整列阳光被毒化 → 除顶部填充行（0xff）
  外全 0 → "太阳光只显示在世界顶部第一层"；
- 流星雨期间空间区有流星质量>0 → 该列 absorb 有限 → 阳光可传播 →
  用户观察"阳光可在气体/有质量物质传播、被纯真空阻隔"（符合 NaN 症状）。

**证据链**：
- 存档解析（03_only.sav）：世界顶部行（sim 384）为真空质量 0；空间区
  sim 344-383 真空；世界 (0,0,256,384) 与 DefineWorldOffsets 一致；
- old 稳定版对 `mass_per_unit==0` 用 multiplier=1.0（默认值）→ 无 NaN →
  光照工作——本修复同款；
- C# 顺序确认：原版也是 `Sim.Start()` 先于 `DefineWorldOffsets`
  （SaveLoader.LoadGame L421/L443）→ "首帧 worlds 空"非本项目独有、非根因。

**修复**：
1. `elements_table.rs`：非固体 `defaultMass > 0` → 1/mass；`defaultMass <= 0`
   （真空等）→ massScale = 1.0（固体仍 INFINITY 全遮光）；

### 阶段 B 实测修复：Constant 发射节奏（2026-08-04，用户实测后内联修复）

**用户实测反馈**：
- 人力粒子发生器间歇性发射 ✓（其 SMI 门控本来就是间歇，正确）；
- 发光虫/冰息萝卜等其余发射器**全部间歇性**（原版应为连续）✗；
- **熔毁反应堆不发射辐射** ✗（原版运行态/熔毁态都持续发射，熔毁后
  4800→0 约 3000s）。
- 用户纠正原版行为：Reactor.cs **L110 on.Enter 显式 SetEmitting(true)**
  （运行态发射，emitRads=2400）；熔毁态 L184 SetEmitting(true) +
  L257 Lerp(4800,0,timeSinceMeltdown/3000)。此前"正常态不发射"结论有误。

**根因（辐射时序两处偏离原版）**：
1. 此前 Update 门控 `emitTimer >= emitRate` 才发 → rate=1 的 Constant
   发射器**每秒才发一次**；而辐射衰减 `rad -= rad/linger`（linger=1.1，
   每 tick 剩约 9%）→ 每秒一次的发射 2~3 tick 内衰减殆尽 → 叠层看起来
   是"间歇性脉冲"；反应堆（rate=1）同理，闪烁几乎不可见 →"不发射"。
2. 原版节奏是 **stepTimer 小数累加器驱动**：step_time=emitSpeed/max_r，
   `n=(int)(dt/step_time)`，n<1 时不发、累加器攒够一个 step_time 补发 1 次
   （帧末 emitStepTimer+=dt、每次发射 -=step_time）→ 半径 6 约 6 次/s、
   半径 25（反应堆）约 20+ 次/s，叠层呈现连续。

**修复（8e4157b，严格对照 11_msvcrt_ignored.c L39693-39881）**：
- Update 重写：timer<=speed 恒可发（rate_ok 时重置 timer/step）；timer>speed
  且 !rate_ok → skip；发射次数按 stepTimer 累加器补发，rate==0 恒 n=1；
  emitStep=(emitStep+1)%max_r 环绕；帧末 emitStepTimer+=dt。
- Modify：emitSpeed = min(emitSpeed, emitRate)（原版 L39168 钳制）；
  **不再重置 emitTimer/emitStep/emitStepTimer**（原版 Modify 不重置，
  灭活期计时冻结、重新激活后续走）。
- 测试：9 条 emitter 测试全过（新增 stepTimer 补发、rate 边界重置 step、
  多步发射+环绕、speed 钳制断言）；全量 466 测试串行全过；release 构建成功。
- **待实测（部署新 DLL）**：发光虫/冰息萝卜应连续辐射；人力粒子发生器仍
  间歇（正确）；蜂巢 Pulsing 节奏；运行态/熔毁态反应堆持续辐射且熔毁
  5 周期（3000s）后归零；单星零辐射不回归。
